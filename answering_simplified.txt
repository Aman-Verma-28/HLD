-> Deep Dives and Trade-offs (12-15 minutes)
    -> Discuss the critical components (Pick 3-4 critical components that explains senior level thinking) (Use your own judgement to pick the critical components)
    -> These components should be likely around event driven architecture, caching, queuing, sharding, distributed systems, etc.
        -> All these points should satisfy the non-functional requirements of the system and the problem domain.
        -> For each critical component, give 3-5 points as below, and consider using a real-world example.
        -> For each critical component give 3-5 points 
        -> First point about the component itself and where it sits 
        -> Second point about the interactions with other components
        -> Third point about why it is critical and why do we need it
        -> Fourth point about the other approaches to solve the problem and the trade-offs
        -> Fifth point about the recommendation and why we chose this approach
        -> Example: Apache Kafka as a Message Queue in an E-commerce Website (between Payment Service, Checkout Service, and Inventory Service)
            -> (1) Kafka is a distributed messaging system that acts as a central queue, sitting between the Checkout Service (producer) and the Payment & Inventory Services (consumers).
            -> (2) The Checkout Service sends (publishes) a message to Kafka when a user places an order. The Payment Service and Inventory Service subscribe to relevant Kafka topics and consume these messages. This enables loosely coupled communication and asynchronous processing.
            -> (3) This is critical for ensuring order reliability and decoupling services—without Kafka, a failure in Payment or Inventory Service could break the end-to-end checkout flow, hurting availability and scalability.
            -> (4) Other approaches could involve direct synchronous API calls (tight coupling, lower resilience) or using other message brokers like RabbitMQ (which may have different durability/performance profiles). Trade-offs involve setup complexity, required throughput, and delivery guarantees.
            -> (5) Kafka is recommended because it provides durability, high throughput, fault-tolerance, message replay, and scalable pub-sub needed for high-volume e-commerce transactions, satisfying non-functional requirements like availability, consistency, reliability, scalability, and eventual consistency for distributed operations.
